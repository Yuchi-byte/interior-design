Renovation context: does telling FLUX it is renovating keep the room?

Study fmrg_context in framework 0002_geometric_guidance · 2026-08-14, local RTX 5090 · FLUX flow-map + LoRA, 2 scenes × 8 arms × seed 0 · commit 8567ab6 · run 19:08–19:11 (~3 min), peak 28.17 GiB

No — context alone does not keep the layout, and the depth reward stays additive at every init strength. At renovation-strength init (σ 0.9, effectively 0.944 after FLUX's mu-shift — ~6% photo signal), phrasing the prompt as "renovate this room … keep the room structure, layout, viewpoint and camera angle" bought −3.6% (scandi) and −5.2% (kitchen) depth error against the style-prompt baseline — statistically nothing; the renders confirm FLUX invents a different room either way. Adding the depth reward on top of the instruction cut the same arms' error −89% and −84% further, landing where the plain guided arm C lands (−86…−89% vs A).

Stronger image context (lower σ) "wins" depth mostly by not renovating. On the kitchen — the scene whose style actually has to change — the σ≤0.75 instruction arms return the photo lightly retextured: depth error collapses to ~0.003, but adherence collapses with it, to 54–59% of baseline. The one regime where context genuinely helped is scandi at σ 0.75: a real renovation (adherence 122% of A) at −43% depth error — and the reward still removed 99% of what remained (0.0799 → 0.0007) at unchanged adherence. Image context sets how much room there is to lose; the depth reward is what actually holds it.

Design

Per scene, one seed (0), eight arms off one transformer load, all scored on the one shell-pixel set every arm left visible, and all judged against the scene's neutral style text (never an arm's own prompt):

  • A — style prompt, σ 0.9, no reward (baseline; the FMRG default control);
  • C — style prompt, σ 0.9, depth reward (the current default guided arm);
  • B@σ — renovation instruction, no reward, σ ∈ {0.6, 0.75, 0.9};
  • D@σ — renovation instruction, depth reward, same sweep.

σ is the pre-shift request; FLUX's resolution-dependent mu-shift warps the 512² grid, so the walks actually start at 0.6 → 0.738, 0.75 → 0.849, 0.9 → 0.944 (read off the resolved schedule, not the config). Scenes: scandi_living_room (FMRG's best-behaved scene) and blue_white_kitchen (its weakest by guided depth error: 0.391 at seed 0 in the 0002 FMRG run, vs 0.018–0.07 elsewhere).

What the renders show: kitchen A and B@0.9 are both entirely invented tall galley kitchens — at effective sigma 0.944 the instruction changed style compliance, not geometry. Kitchen B@0.6/D@0.6 are the original room with the palette gently shifted — no industrial renovation happened. Confounds, honestly

The not-renovating trap is live in this data. Every kitchen arm at σ≤0.75 posted a near-zero depth error and an adherence ratio collapsed to 54–59% of baseline: those arms won depth by returning the photo. The depth column alone would call them the best arms of the study; the adherence column is what exposes them. Their shell coverage also rose (88–96%) — an untouched room segments cleanly — which is why coverage is a diagnostic, not a guard.

Scandi adherence cannot fully expose that trap. The scandi scene's photo already matches its own style prompt ("scandinavian living room" → scandinavian living room), so a copied photo still scores well on CLIP there — B@0.6's 104% ratio is not proof it renovated. The renders say it changed furniture modestly; the kitchen, whose style had to move, is the informative scene for this confound.

One seed, two scenes. This is the owner's fast-iteration setting; the σ0.9 conclusions match the 0002 FMRG benchmark's 32-pair direction, but the σ-sweep findings rest on single samples.

Adherence judge changed vs older reports. This study scores with ViT-L/14 (eval-only, never the guidance CLIP — now enforced by a config validator); 0002's FMRG run used ViT-B/32, so absolute adherence values are not comparable across reports. Ratios vs each study's own arm A are.

Methods

Config experiments/0002_geometric_guidance/conf/context.yaml; runner run.py --config context; results outputs/0002_fmrg_context/results.json. Sampler: FMRG fmrgj_nfe100 point — 208-sigma grid truncated at 51, one terminal jump, endpoint-reuse stepping, decoder-only pullback, eta 5.0, resegment on, erosion 2. Seed 0 via an explicit per-walk torch.Generator; deterministic kernels requested. Style prompts are 0002's verbatim: "a scandinavian style living room, pale oak furniture, linen upholstery, soft daylight" / "a modern industrial kitchen, matte black cabinetry, steel shelving, concrete worktops". Renovation prompts prepend/append the instruction only: "renovate this room into <style>, keep the room structure, layout, viewpoint and camera angle" — style descriptors identical, so the prompt axis varies framing alone. Adherence: CLIP ViT-L/14 (openai/clip-vit-large-patch14) against the neutral style text for every arm, loaded only after the last walk (a resident ViT-L beside FLUX's backward transient OOM'd a 32 GB card on the first attempt). Depth: DA2-Small, scale-and-shift aligned via align_scale_shift over the common shell mask. Unguided walks 8.0 s, guided 12.8 s; whole run ≈3 min wall-clock; peak 28.17 GiB (guided arms), 24.7 GiB (unguided).
